# SA Functional Requirements / Use Cases

## 目標
建立前後端登入與 RBAC 系統，涵蓋登入/登出、權限控管、多裝置會話、逾時與撤銷、稽核與安全政策。

## Use Cases
- UC1 登入：使用者以帳號/密碼登入，成功取得 access/refresh token，失敗顯示非敏感訊息。
- UC2 登出/撤銷：使用者主動登出或管理員撤銷，access/refresh 立即失效，跨裝置阻擋後續請求。
- UC3 閒置逾時：30 分鐘無操作自動登出並提示。
- UC4 鎖定策略：連續 5 次登入失敗鎖定 15 分鐘；鎖定期間拒絕登入並提示。
- UC5 角色與權限配置：管理員建立/更新/刪除角色，配置權限並指派給使用者，即時生效。
- UC6 授權檢查：受保護資源按角色/權限判斷，無權請求返回 403 並記錄稽核。
- UC7 稽核查詢：管理員可查詢登入/登出/拒絕/角色變更等事件，支援篩選。

## User Stories
- US1（P1）：身為使用者，我需要安全登入與登出，並在閒置後自動登出，以保護帳戶。
- US2（P1）：身為系統管理員，我需要定義角色與權限並指派給使用者，以控制可存取的功能。
- US3（P2）：身為安全/稽核人員，我需要完整的登入/授權/變更紀錄並可查詢，以便調查與回溯。

## 範圍界線
- 聚焦本地帳號/密碼與 PostgreSQL 自管，不含外部 IdP/OIDC。
- 僅涵蓋網頁前端（Angular）與 REST 後端（Spring Boot），不含行動端。
- 只處理 RBAC，不含 ABAC/細粒度策略語言。

## 非功能需求摘要
- 效能：API p95 < 300ms；登入 90% 於 5 秒內完成；首屏可互動 < 2.5s。
- 安全：bcrypt 雜湊、token 簽章、TLS 準備、CORS/Cookie 安全設定、鎖定/撤銷策略。
- 可觀測性：記錄登入/登出/拒絕/變更事件，結構化日誌；必要指標（延遲、錯誤率）。
